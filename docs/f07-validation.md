# F07 validation

The owner accepted D20 on 6 October 2026: no containers; native Ubuntu WSL PostgreSQL, Keycloak and API services with a PowerShell entry point, generated private secrets, separate databases/roles, two developers plus an operator, real authorization-code/S256 PKCE login and retained data during ordinary stop. This amends the original Kubernetes-specific F07 checklist. Temporal follows its workflow ticket.

Implementation: [native driver](../deploy/native/stack.py), [private launchers](../deploy/native/runtime.py), [realm template](../deploy/native/realm.json), [PowerShell entry point](../scripts/local-stack.ps1), [one-shot login helper](../cmd/forge-login/main.go), [real native smoke](../deploy/native/smoke.py) and [operator guide](local-stack.md).

Local results: native PostgreSQL 18.6, Keycloak 26.8.0 (verified official archive) and OpenJDK 21.0.12.1 start and pass readiness. Windows reaches the API and exact issuer through loopback, including after orderly teardown/restart. Real Keycloak authorization-code/S256 PKCE through the actual login helper passed for two developers and the operator; wrong/missing PKCE and disabled password grant are rejected. Owner workload/version creation/read, denied cross-owner read/update, operator inspection, operator cross-owner mutation denial and unauthenticated rejection passed. Stop released the API port; restart retained the workload/version, all three identity subjects and cursor key. Live retained product data was preserved.

Windows formatting/module verification/vet/build and 29 top-level tests/43 named subtests passed, with zero failures. Ubuntu required real-PostgreSQL race checks passed with 32 top-level tests/65 named subtests and zero failures. Five native lifecycle guard tests passed, including preservation of unmarked data and rejection of unsafe purge targets/confirmation/active state. Govulncheck v1.8.0 found no vulnerabilities. The Windows sandbox blocks temporary-file rename; those Windows checks were run outside that restriction, and Linux exercises private atomic token replacement normally.

The native CI job starts an isolated fresh installation without containers, exercises the real login/API smoke, performs orderly stop with retained-file checks, restarts and revalidates identities/records/key, then tears down services. Existing Windows/Ubuntu and required PostgreSQL/race/restart jobs remain. Exact published commit/CI evidence is recorded on the F07 card after all corresponding jobs pass; no uncompleted CI result is claimed here.

Limitations: local HTTP and Keycloak development mode are intentional operator-local configuration; no production identity/TLS claim. Services are started on demand rather than enabled at Windows boot; a hidden WSL lifetime helper holds the VM while this stack runs. Host administrators/service owners can inspect local secrets and SQL. The smoke performs the actual Keycloak authorization form, PKCE code exchange, callback and signature/role verification over HTTP; it is not a visual browser usability test. No model call, Temporal worker/run HTTP endpoint, backup/crash-recovery objective or Kubernetes deployment is introduced. Clean stop/restart demonstrates retained local persistence, not high availability. Live retained product data is never purged by validation.
